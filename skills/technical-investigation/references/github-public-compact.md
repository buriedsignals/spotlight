# Public GitHub History — Compact

Use only public profiles, repositories, commits, forks, tags, releases, issues, and archived public pages relevant to the case.

1. Define the repository/account question and date range.
2. Preserve stable URLs, owner/repo names, commit SHAs, timestamps, API fields, and collection UTC.
3. Compare repository history, forks, releases, and public archive captures for changes or deletions.
4. Separate authored, committed, pushed, merged, and published events. Names and emails in Git metadata are self-asserted and do not prove identity.
5. Record null/skipped/blocked paths and rate/visibility limits.
6. Seek an independent source before attributing code, control, employment, intent, location, or identity.

Do not hunt for secrets, validate credentials, infer working hours/personality, access private material, or contact maintainers through the platform.
