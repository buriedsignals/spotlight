How Spotlight works.

A versioned skill bundle that turns any AI agent runtime into an OSINT investigation pipeline. Brief → methodology → research → investigation cycles → investigation gate → report → intelligence base. Open by default; opt-in sensitive track for local-model sessions.

01 — What it isAn OSINT pipeline you check into your repo.

Spotlight is a set of skills, agent prompts, schemas, and verification rules stored as version-controlled markdown. You point your AI agent runtime at the bundle, give it a lead, and it walks the investigation end-to-end: planning the methodology, running search and scrape cycles, archiving evidence locally before citing it, fact-checking with an independent pass, and writing the result into an intelligence base you own.

The point isn't to replace the journalist. The point is to remove rote work — link-walking, archive-before-cite, schema compliance, citation hygiene, fact-check provenance — so editorial time goes to judgement and source work, not to babysitting the agent.

Everything in the bundle is editable. If your newsroom needs a different verdict taxonomy or a custom integration, you fork the repo, edit the markdown, and your agent picks up the change next session.

02 — The pipelineSeven named phases, six gates.

Every investigation runs through the same named phases. The agent moves between them under explicit gates, so nothing advances without you. Research runs only when you switch it on in the app. With it off, the case goes from Methodology straight to Investigation.

Orchestration · local

💻The Pi harness

A launcher starts the orchestrator, the investigator, the fact-checker and the analyst as separate Pi processes. Workers start only when the orchestrator asks, one per task, and cannot delegate.

There is no shell. Every step a skill would run in a shell is a typed tool, or a check the harness runs itself when a worker finishes. The model never records a gate decision, and case state lives on disk, so a closed chat loses nothing.

Checks run at fixed points

Orchestration · subscription

☁️Skill-based orchestration

Your agent app (Claude Code or Codex, on your own subscription) loads the Spotlight orchestration skill and walks the same phases. It spawns the investigator, fact-checker and researchers as its own subagents and runs Spotlight's scripts to check each step.

The gates, schemas and case folder are the same as in the local harness, so a case reads the same whichever way it ran.

The gates still wait for you

✦ Members

🧭OSINT Navigator

While it writes the methodology, the investigator asks Navigator for the right OSINT tool for each direction (registries, domains, usernames, images, archives and more) and records why it chose each one. A check confirms the plan followed those lookups before you see it.

Without a membership, the investigator picks from a local tool index instead, with no outside call. Sensitive mode makes no Navigator request at all.

🧩Indicator Framework

For questions about whether sites, accounts or domains are linked, and who runs them, the methodology can turn on the Indicator Framework. The investigator and the fact-checker rate the indicators, and the case gets a ratings sheet with flags and tasks.

At the Investigation gate you review those flags and tasks and can assign them to a follow-up cycle. The framework never changes a finding's confidence or grounding.

Start

🎯A lead

A URL, a document or a name. The cases root is trusted, journalist-owned local storage, and every case lives in its own folder there. Active case directories must not be moved or replaced during an operation.

Phase 01

🧰Preflight

Runtime check, intelligence base check, integrations check. Spotlight refuses to start if the intelligence base is unreadable, the bundled scraping and search stack isn't responding, or a required external tool is missing. Failures are explained in plain English, and no work happens until the environment is sound.

Phase 02 · gate

📝Brief

The agent restates the lead in its own words, names the affected parties, sets a scope and writes a hypothesis. You read it back. If the agent has misunderstood the lead, you correct it here. Redirecting in two sentences now is faster than three investigation cycles later.

You approve the brief

Phase 03 · gate

🗺️Methodology

The agent writes a methodology JSON. It names the entities to investigate, the sources to consult (corporate registries, social media, archived web, OSINT Navigator tool lookups) and the fact-check threshold. The file is editable, and the investigation follows it.

When Research is switched on, the methodology also proposes research topics. Each topic is a short brief on one lane type (web, registries, archives, social, technical, news and courts, local corpus, prior knowledge or ad hoc) with a round budget.

You approve, edit, delete or add topics

Phase 04 · research lanes

🐝The swarm collects

Code, never the model, runs each approved topic as its own research lane. Web lanes run on the OpenRouter swarm with your own key, or on your frontier host's subagents. Local lanes search your case files and your wiki on the local model.

A web lane gets only its topic brief. It never sees case files, findings, evidence or journalist input. A budget of $1 a round by default, and at most $5 per case, bounds the web lanes.

Lanes run in parallel

Phase 04 · checks and gate

🔎Checks, triage, your marks

Each lane returns leads with a summary, an exact quote and the source it saved. Code checks every quote against the saved source, merges copies of the same source, and applies fixed clue rules for convergence, conflicts, timing, shared identifiers, expected absence and the watchlist.

A decision model then triages the leads. Triage only flags leads and never sets one aside on a model answer.

The Research page shows the clues first. You mark each clue pursue or dismiss and each direction keep, drop or add, then approve in one stop. Code checks that the methodology change matches your marks.

Code checks quotes You mark the clues

✦ For members

Ninja mode runs triage on your own Mac. Fixed rules do it until the local decision model ships.

Subscription mode sends the triage questions to the Jev decision model on OpenRouter.

Phase 05 · cycles

🔁Investigation cycles

Up to three cycles. The investigator follows the approved methodology in EXECUTION mode. Every source is archived locally before it can be cited, and every claim gets an evidence trail with a grounding rationale. A separate fact-checker agent then verifies the claims.

If the readiness check fails, the case loops. After three cycles, a case with Research on goes back for one targeted research round, and your approval grants one more cycle. If it still isn't ready, it stops with a gaps report.

Readiness is checked by code

Phase 05 · gate

🚦Six checks before the gate

  1. Findings are non-empty and schema-valid.
  2. The fact-checker ran as a separate agent, outside the investigator's context.
  3. Contradictions in the evidence are recorded.
  4. The affected party's perspective was sought where the lead names one.
  5. Every source has an access_method and a local file.
  6. What we don't know is named in a gap assessment.

You review the findings

Phase 06 · gate

📄Report

After the Investigation gate you complete or decline the report. A completed report publishes report.html, findings-report.md and evidence-map.json as one validated package before the case can move on to ingest.

You decide on the report

Phase 07 · gate

🗄️Ingest

During a case, source archives and working JSON stay in the case folder. After you approve, Spotlight writes the approved knowledge to your wiki under spotlight/ as claim, event and story-arc notes. Later investigations search the wiki for prior work and build on it.

You approve what enters the wiki

03 — SkillsThe skills that compose the pipeline.

Each skill is a markdown file with a frontmatter contract (name, description, allowed verbs). The agent loads them at runtime. You can edit any of them.

The one under every finding is epistemic grounding. Spotlight treats a source as an anchor that still has to justify the claim, so each finding records the exact quote, the source's role, the kind of support it gives and a confidence cap. The fact-checker then writes its own grounding assessment, and only directly grounded or independently verified claims can become high-confidence findings. How grounding works ↗

04 — RuntimesUse the agent you already have.

Spotlight is runtime-agnostic. The same skill bundle drives any agent that can read markdown skills and call shell tools.

☁️Cloud runtimes

Claude Code, Codex CLI, Pi, and OpenCode (routed to OpenRouter / Fireworks / Together) all work natively. Authentication is via each runtime's own login — no API key needed for the subscription-backed ones (Claude, Codex, Pi), and a provider key for OpenCode pay-per-token.

Cloud runtimes are the right choice for open material — public-record research, archived web, corporate filings. They're faster and more capable than what fits on a laptop, and the trade-off is that the agent's context goes to the third-party provider.

💻Local runtimes

OpenCode pointed at a local Ollama endpoint keeps everything on the journalist's machine. The installer ships two abliterated journalism models:

  • Default — Qwen 3.5 9B Journalist (tomvaillant/qwen3.5-9b-abliterated-journalist-GGUF:Q4_K_M). 9B dense, ~6 GB on disk, fits 16 GB Macs comfortably. Bench-tested at 100% refusal-resistance on OSINT-grade prompts.
  • Heavy tier — Qwen 3.6 27B Journalist (tomvaillant/qwen3.6-27b-abliterated-journalist-GGUF:Q4_K_M). 27B dense, fine-tuned on the same investigative-journalism corpus as the 9B, on Huihui's abliterated Qwen 3.6 base. ~15 GB on disk, ~22 GB resident at runtime. Runs in thinking mode (the abliterated /no_think path produces token soup). Needs 32 GB unified memory minimum — the setup form's fit-check enforces this before the option commits.

Local runtimes are slower than cloud runtimes — the 9B does an investigation in ~15 min vs ~5 min on cloud; the 27B takes 45–90 min. They're the right choice when material can't leave the machine.

🧮Hardware fit-check

The local configurator the installer opens probes your hardware via navigator.deviceMemory + WebGPU and recommends a model: 9B Journalist for any 16 GB+ Mac (default), the 27B if RAM reports ≥ 32 GB. Below 16 GB it pushes users to Frontier mode.

05 — ConfigurationOne install, browser-connected research.

The public installer offers a direct local browser sign-in for Navigator or an explicit Skip. A successful Pro or Lab connection stores a revocable credential in the system keychain; no Navigator API key is pasted into Spotlight configuration.

🔑Required 
SPOTLIGHT_CASES_ROOT=~/Documents/Spotlight/cases  # active case workspace

Your wiki is knowledge_destination.workspace_path in .spotlight-config.json. Ingest writes there and later cases search it.

Search and scraping need no key: fetch runs on Crawl4AI and search on SearXNG, both open-source and installed locally. FIRECRAWL_API_KEY=fc-... is optional — set it only to enable Firecrawl as an explicit fallback provider.

SPOTLIGHT_MODEL_TIER=12b                      # 12b / 26b / 31b — sets reasoning budget + compaction profile

06 — Sensitive modeLocal-only investigations first.

Spotlight investigations default to open material. For source-protected documents, off-record interview notes, unpublished tip identities, or other sensitive material, use runtime-level sensitive mode so agents work from local case files and intelligence base context instead of live network acquisition.

Current support

The current installer initializes one OpenKnowledge project and does not create a second sensitive project or route. The implemented control is the runtime contract's sensitive mode: when enabled, adapters strip live fetch and search access and the case must be worked from local material.

⚙️How it works
  • Set sensitive: true in AGENTS.md or use the equivalent runtime command when your adapter supports it.
  • Preload material into the resolved {CASE_DIR}/research/ workspace and the local intelligence base before starting the sensitive investigation.
  • Do not rely on sensitive-vault commands from the design spec until they are implemented in setup, ingest, and doctor checks.
🧭What this is and what it isn't

This is plumbing, not enforcement. Sensitive mode reduces accidental network use by the Spotlight adapter, but it is not a host security boundary. It does not stop a sufficiently privileged local agent from using unrelated shell or search tools outside the Spotlight contract.

If your threat model requires that level of guarantee, run sensitive work on a separate machine and treat the sensitive vault on the laptop as a summary archive of work done elsewhere — not as the workspace for the sensitive investigation itself. The design spec on GitHub walks through why earlier drafts proposed UID separation and air-gap phases, why those were cut, and what's left.

🗺️Suggested workflow
  1. Open research happens via the normal Spotlight pipeline against your default intelligence base, under whichever runtime is best for the material (usually cloud).
  2. If a sensitive piece arrives, work on it in your own environment — local model on an isolated machine, encrypted disk, paper, whatever matches your operational layer.
  3. When you're ready, write sanitized outputs into the normal case files or keep them in a separately managed local vault until the sensitive-vault workflow is implemented.
  4. Declassification (moving a finding from sensitive to open) is a manual file copy + re-ingest — no special command, by design.

07 — FAQCommon questions.

☁️Is Spotlight a SaaS?

No. Spotlight is a markdown skill bundle you check out from GitHub and point your existing agent at. There's no Spotlight server or Spotlight account. Search and scraping run on bundled open-source tools (SearXNG, Crawl4AI) with no account; Navigator is an optional member integration.

💸What does it cost?

The Spotlight bundle itself is free and open-source (MIT). Costs come from whatever runtime you choose:

  • Claude Code / Codex CLI / Pi — covered by your existing subscription (Claude Max, ChatGPT Plus/Pro/Team, or a supported Pi subscription).
  • OpenCode — pay-per-token through OpenRouter / Fireworks / Together. Roughly $0.50–$2 per investigation.
  • Local model — free at runtime; one-time disk cost for the model weights (~7 GB for the tuned Gemma-4 12B Q4, ~18–22 GB for the 26B tier).

Search and scraping are open-source and free (SearXNG + Crawl4AI; Firecrawl is an optional keyed fallback). Pro and Lab members can connect OSINT Navigator for tool discovery.

🤖Why does the runtime matter?

Different runtimes have different trust properties. Cloud runtimes send the agent's context to a third-party provider — fine for open material, not fine for sensitive material. Local runtimes keep the context on the journalist's machine. The journalist picks the runtime per session; there's no automatic switching.

✅How is fact-checking different from the main investigation?

The fact-check pass runs as an independent agent spawn — a fresh context, separate from the investigator. It applies SIFT methodology (Stop, Investigate the source, Find better coverage, Trace claims), produces one of five verdicts (verified / unverified / disputed / false / not_checkable), with flags for claims that misstate their source, and writes its evidence trail to a separate JSON. The investigator can't see the fact-checker's output until after the Investigation gate. This is deliberately adversarial — same-context fact-checking under-catches errors the investigator already convinced itself of.

🔒What's the sensitive vault flag for?

It is a proposed second OpenKnowledge project for deliberately classified material. It is not implemented, and a separate project alone would be a convenience boundary rather than a confidentiality guarantee. Use an appropriate operational boundary — such as a separate machine or OS account — for material whose threat model requires isolation.

🧩Can I bring my own skills / custom integrations?

Yes. Fork the repo, add a skill folder under skills/ with a SKILL.md matching the frontmatter contract, register it in AGENTS.md. Your runtime picks it up next session. The 13-verb runtime contract is the only thing that has to stay stable; everything else is editable.

🧱What happens if the agent gets stuck?

After three investigation cycles without passing the Investigation gate's readiness criteria, a case with a research plan goes back to Research for one targeted round, which you approve on the Research page; that grants one more cycle. If that cycle fails too, or the case has no research plan, the case stops with a gaps report: every gap the cycles recorded. Continuing takes a revised methodology and a new approval. No investigation silently abandons.

🔏Where does provenance live?

Each case produces a provenance-manifest.json built against the Noosphere C2PA contract. By default it's unsigned (the signing block exists but credential / endpoint are null); newsrooms that have a Noosphere signing setup can wire it in via the provenance-signing skill. The manifest tracks ingestion events, fact-check verdicts, and (when enabled) tier transitions.

🐛Where do I file bugs or contribute?

Issues, PRs, and discussions on GitHub: github.com/buriedsignals/spotlight. The contribution guide is at CONTRIBUTING.md in the repo root.
