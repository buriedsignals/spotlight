Engineering log · Sovereign local tier

Going sovereign.
A full investigation system on a 12B, on my laptop.

Spotlight — my gated, multi-agent OSINT investigation system — has offered local models from the start. Honestly, they never worked well for me. Anything capable enough wanted a bigger machine than my 48 GB MacBook; anything that fit either drowned in the system prompt or fell over the moment an investigation outgrew its context window. So I embarked on a quest: make Spotlight truly work locally. It took weeks of iteration, effort, and an embarrassing number of tokens — but it happened. And the way there produced a stack of efficiency leaps that matter to any newsroom that wants to own its AI: repeatable investigative workflows that don't scale cost with usage and don't sacrifice privacy. This is how I did it.

The quest Run Spotlight's full gated pipeline — orchestrator, investigator, fact-checker, human gates — on a 48 GB laptop and a 12-billion-parameter open model. No API calls. No per-token bill. Nothing leaves the machine.

How each number happened is the story below.

Five unlocks got it there, each one forced by the failure the previous one exposed. The pattern behind all five: almost every "the model can't do this" turned out to be an engineering problem wearing a capability costume.

01

Efficiency unlock · the context floor

Dynamic skill loading — collapse the floor

Where things stood at the start: Spotlight's methodology lives in skills — markdown procedure files for investigation phases, fact-checking, provenance, ethics — and the frontier-shaped harness loaded all of it up front. A ~55,000-token floor before the first user word. On my machine that meant ~34 seconds of prompt processing before every conversation, and a context window already half-spent before the model had done anything. The first unlock was architectural, not clever: skills are discovered by name and description only; bodies load when a skill is invoked.

But it wasn't enough. The 12B still collapsed — and the audit pointed at the pages themselves: every scrape dumped ~40,000 tokens of boilerplate into a context the model stops behaving in past ~16k.

02

Efficiency unlock · the RLM

Scrapes never enter context raw

So I dove into the RLM — a research language model: a second, tiny model resident beside the orchestrator (a Gemma e4b on its own llama.cpp), whose whole job is to read the noise so the investigator doesn't have to.

Every fetch pipes through it automatically, and the agent receives a compact, source-linked lead list; the raw page stays on disk as a .raw sidecar, because compression must never destroy evidence. The automatically matters: an early experiment exposed distillation as a skill the model could invoke. The weak 12B simply never did, and drowned. Anything a small model must do for its own survival belongs in the harness, not in its judgment.

Then I pushed the same trick onto the conversation itself. Each Spotlight phase already writes a compact artifact (methodology.json, findings, verdicts) — the artifacts are the state; the transcript between gates is disposable. So past a fold threshold (~16k tokens for the 12B) the RLM rewrites the conversation into a structured checkpoint, off the main model's critical path. Measured on a real stalled run: 40,180 tokens folded to ~10,200 — and the model that had been thrashing delegated correctly on its very next turn. Depth kills discipline; the same 12B loops uselessly at 40k of context and reasons crisply at 13k. Compaction turned out to be a behaviour lever wearing a performance-lever costume.

Still not enough. Fetches were lean now, but the failure log kept filling — and when I audited it, half the "model failures" weren't the model at all. They were the harness lying to it.

03

Efficiency unlock · the harness

Harness engineering — one harness, real subagents

So I dove into the harness. The non-frontier harness is a Flue app built on Pi — and the exact app my evals exercise is the app the installer deploys. Local test == user experience; never build a parallel dev harness. Delegation is real: the investigator and fact-checker run in their own child sessions, so fact-check independence is structural, not a prompt promise. The rest of what keeps a small model alive:

  • A verb adapter: skills speak abstract verbs (fetch, search, spawn-agent…); a runtime adapter binds them to concrete tools, absolute paths baked in. Two of the nastiest "model failures" were the adapter resolving the wrong path — the model falls back to raw curl and looks stupid.
  • Durable sessions: every conversation persists to SQLite; a crash or a closed lid resumes on the same session id. Gates become ordinary turns.
  • Guard rails: subagents carry a never-re-delegate guard (a 12B will happily recurse task→task→task until the run dies); gates are enforced on every path.

And the context overhead dropped again: the open tier's OSINT tool catalogue — an 11,800-token block of permanent context — became a local SQLite full-text index the model queries with one shell call. Permanent context should be an index, never a payload.

STILL not enough. The plumbing was honest, the context lean — but the model wouldn't hold the procedure. It re-activated skills it had already read, researched instead of delegating, and talked straight through gates.

04

Efficiency unlock · the tune

Procedure tuning, not capability tuning

So I stopped doing what I'd always done — capability tuning — and tuned the procedure instead. Don't tune for what the model knows; tune for what it does. Gemma-4 12B already knows what a commercial registry is. What it couldn't do was hold a gated, multi-turn procedure: activate the methodology skill once, advance on a bare "approved", delegate instead of researching itself, stop at the gate. Procedural behaviours are learnable from a tiny dataset — if the data is shaped right. What went into it:

12 gold trajectories 30–46k tokens each real runs · human-approved gates assistant-masked loss ~$10 of rented H100
v1 QLoRA · full-text loss · 3.00 Learned the style — 2.8× faster to a correct first-turn brief — then stalled the pipeline. Tool outputs dilute the signal. ✗ stalled
v2 assistant-masked · 0.79 Learns decisions, not tool noise. Then an adapter merged in a mismatched stack produced garbage GGUF. ✗ corrupted merge
v2-fixed matched train/merge stack Coherent again — a milder stall, and every eval learning banked. A five-second coherence check now runs before quantisation. △ milder stall
v3 shipping orchestrator The model the installer pulls today. Total spend across every iteration: about ten dollars. ✓ ships
v4 in training now Simulated trajectories drilling the exact failure modes the evals exposed: phase-advance on bare approval, recovery from a degenerate turn. ⟳ training

The model: gemma4-12b-spotlight-orchestrator-v3-GGUF (Q4_K_M, ~7 GB), trained from spotlight-orchestrator-gold.

And even then it kept dying — at the methodology gate, mid-investigation, every single eval, around 28–30k tokens. I started to despair. Then the server logs confessed: it wasn't the model at all.

05

Efficiency unlock · serving

KV-cache and serving — the invisible half of local

failed to find available cells in kv cache, then failed to restore state with size ~971MB. The serving layer was saving and clearing the orchestrator's KV state on every delegation, then failing to restore it. The fix took me deeper into how the model is served than I'd ever planned to go — and it turns out small-model agentic serving has its own discipline:

LeverSettingEffect
Resident slots--parallel 2 --no-cache-idle-slotsOrchestrator + active subagent each keep a live slot; nothing saved/restored on delegation. The fix — and one slot is worse than two.
KV quantisation--cache-type-k/v q8_0 + --flash-attn on≈½ the KV memory per token — double the effective context, near-lossless.
Context geometry--ctx-size 81920 ÷ 2 slots40,960 tokens per agent — past any point the bounded pipeline reaches.
Reasoning budget--reasoning-budget 400 (12b)Unbounded thinking spends the whole output budget and returns an empty reply. Capped: think briefly, then act. 800 for the 26B, 1024 for the 31B.
RLM serving--reasoning-budget 0A distiller must answer, not think.

None of this applies to API deployments — the same harness detects the tier and serves frontier models unrestricted. The constraints live exactly where the constraint exists: on the device.

A concrete run, from last night: resuming a real investigation, the tuned 12B — on a bare "Approved, proceed." — reviewed the corpus, delegated, produced a correct synthesis (the target organisation's president, co-executive directors, legal form and domicile), and stopped at the review gate. On my laptop. The marginal cost was electricity.

To be precise about the claim: not "a 12B is as good as a frontier model." It's that a 12B inside a deeply engineered procedure executes gated multi-agent investigations at usable speed, with the human at the gates. And every optimisation transfers upward — the 26B and 31B tiers inherit the same harness with looser leashes and run better for it. Tune the procedure for the smallest model; the bigger ones get it for free.

The recipe, for newsrooms 1 — Collapse the context floor: dynamic skill loading, indexes not payloads.
2 — Bound the context: automatic distillation of everything scraped; fold conversations into checkpoints; artifacts on disk are the state.
3 — Engineer the harness: real subagents, absolute paths, durable sessions, one harness for eval and production.
4 — Tune the procedure, not the capability: a dozen real trajectories with masked loss beat any amount of domain data. Budget: tens of dollars.
5 — Serve deliberately: resident slots, quantised KV, capped reasoning.

Own the model. Own the harness. Own the data. That's sovereignty — and it now fits on a laptop.

Spotlight is open source — harness, installer, skills, and this entire optimisation stack are in the repo; the local tier installs with one script from the setup page.
