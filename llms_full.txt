# Spotlight — full public AI reference

> An investigation workflow for AI agents, built for journalists. Spotlight takes a reporting lead through an approved methodology, evidence gathering, independent fact-checking, and editorial review, keeping the work in a local case folder.

## When to use it

Give Spotlight a lead, question, URL, document, or entity when you need to develop an investigation. It works with you on the brief and methodology, gathers and saves sources, runs investigation and independent fact-checking cycles, and brings the findings back for editorial review.

**Input:** a reporting lead and an approved scope. **Output:** a local case folder containing evidence, source-linked findings, fact-check verdicts, gaps, and review/report artifacts. A completed agent run is not permission to publish.

Spotlight owns the casework. Navigator helps find methods and tools; Scoutpost monitors sources over time; Anomaly provides data-source context and deterministic checks; Splash produces publication visuals from approved reporting. Each integration depends on the installed release and its configured capabilities.

## Core concepts

- **Pipeline:** Preflight -> Brief -> Methodology -> Investigation cycles -> Investigation gate -> Report -> Ingest
- **Two-agent model:** investigator executes the research; fact-checker independently verifies the claims
- **Editorial control:** the user approves the brief, methodology, Investigation gate summary, and ingestion
- **Readiness criteria:** minimum findings, source independence, no unresolved disputes, affected perspective, document trail, and gap assessment
- **Evidence grounding:** scrape before cite, keep local copies, and archive sources before relying on them
- **Sensitive mode:** strips web search and scraping so investigations can run local-only

## Investigation stages in more detail

The current workflow has seven named phases: Preflight, Brief, Methodology, optional Research, Investigation, Report, and Ingest. Research is present only when the approved methodology includes a research plan. A gate requires an explicit journalist decision; silence, an artifact appearing, or an agent finishing does not approve it.

1. **Preflight:** check the selected runtime, configuration, available skills and integrations, local case storage, and prior or duplicate work.
2. **Brief:** read the lead, agree the scope and directions with the journalist, and obtain approval.
3. **Methodology:** the investigator plans the questions, methods, sources, and any research topics. The journalist approves the plan before execution.
4. **Research, when planned:** approved topics become research lanes. Saved leads and quotes are checked; the journalist marks clues and directions before the methodology is amended.
5. **Investigation:** the investigator gathers evidence and writes findings; an independent fact-checker checks the claims. Up to three cycles address gaps. A researched case may return for one targeted research round; otherwise unresolved gaps stop the work for editorial direction.
6. **Report:** the journalist decides whether to produce a report. Drafting and rendering retain the findings and evidence trail; the report decision is separate from approving the investigation.
7. **Ingest:** verified material is promoted to the knowledge system only through a requested, approved transition. Do not infer permission to write into the wiki from the existence of a report.

See [Investigating](https://spotlight.buriedsignals.com/docs/investigating.md) for the full gate and recovery contract.

## Research and data boundaries

Research over local case files and the wiki runs on the local model. Cloud research lanes are opt-in and receive their approved topic brief, not the full case, findings, evidence, or journalist input. Availability and budgets depend on runtime and configuration. Provider failure stops with a repair message; it does not silently change the execution model.

A local-capable investigation can still use hosted search, scraping, or other integrations. Inspect the selected runtime and acquisition path before making a privacy assumption. Sensitive mode is the local-only path described in the runtime contract.

Anomaly can supply data-source context and deterministic table checks where the installed integration supports it. A detector signal is a lead; Spotlight and the journalist still need to investigate and assess it.

## Evidence and review

The investigator and fact-checker have separate responsibilities. Source material is retained locally before it is cited. Findings carry evidence, confidence, limitations, and source references; fact-check verdicts do not replace the journalist's decision.

The Investigation gate checks enough high-confidence findings, independent source support, unresolved disputes, affected or non-official perspectives where relevant, a primary-document trail, and stated or resolved gaps. A blocked case should report its gaps rather than manufacture readiness.

## Case artifacts

A case folder contains the approved brief, `data/methodology.json`, investigation findings and logs, `data/fact-check.json`, saved research and evidence, and a review summary. Research-enabled cases also hold topic-lane results and marked clues. Activated cases can carry source expressions, source positions, and provenance records. Report outputs and knowledge-ingestion artifacts depend on the journalist's decisions and the case version.

## Installation and runtime requirements

Engine (`bsig`) is the managed installation authority; Indicator Labs provides guided setup. A source-only route exists for agents and developers working from a checkout, without managed credentials, updates, or repair. Follow the current installation reference rather than a copied shell command from an older release.

The execution host needs local filesystem and shell access to the same checkout, dependencies, and durable case storage. Hosted model inference through a local harness can fit that arrangement; a remote agent without those files cannot assume it can run the workflow.
